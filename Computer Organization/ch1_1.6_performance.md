# 1.6 效能（Performance）

> Computer Organization and Design: The Hardware/Software Interface (6th Edition)

---

## 本節涵蓋主題

| 主題 | 說明 |
|---|---|
| 定義效能 | 不同指標得出不同「最好」 |
| Response time vs. Throughput | 完成單一工作的時間 vs. 單位時間完成的工作量 |
| Relative performance | Performance = 1 / Execution time |
| Elapsed time vs. CPU time | 總時間 vs. CPU 實際處理該工作的時間 |
| CPU clocking | Clock period、clock rate |
| CPU time 公式 | Cycles × cycle time |
| Instruction count 與 CPI | 完整效能方程式 |
| 影響效能的因素 | 演算法、語言、編譯器、ISA |

## 1. 定義效能（Defining Performance）

投影片以飛機比較：

| 指標 | 最佳機種 |
|---|---|
| Passenger capacity | Airbus A380-800 |
| Cruising range | Boeing 777-200LR |
| Cruising speed | BAC/Sud Concorde |
| Passenger throughput（乘客數 × 速度） | Airbus A380-800 |

> 「哪一個效能最好」**取決於採用哪個指標**。計算機也一樣。

---

## 2. 反應時間與處理量（Response Time and Throughput）

| 名詞 | 定義 | 例子 |
|---|---|---|
| **Response time**（反應時間 / execution time） | 完成一件工作所需時間，包含硬碟存取、記憶體存取、I/O、OS overhead | 執行一支程式花幾秒 |
| **Throughput**（處理量 / bandwidth） | 單位時間內完成的總工作量 | 每小時處理幾筆交易 |

### 兩種改善方式的影響

| 改善方式 | Response time | Throughput |
|---|---|---|
| 換成更快的處理器 | ✅ 改善 | ✅ 改善 |
| 增加處理器數量（各工作獨立） | ❌ 不變（單一工作不會更快） | ✅ 改善 |

> 降低 response time 幾乎總能提升 throughput；反之不一定。本章先聚焦 **response time**。

---

## 3. 相對效能（Relative Performance）

$$
\text{Performance} = \frac{1}{\text{Execution time}}
$$

「X 比 Y 快 n 倍（X is n times faster than Y）」：

$$
\frac{\text{Performance}_X}{\text{Performance}_Y} = \frac{\text{Execution time}_Y}{\text{Execution time}_X} = n
$$

### 範例

程式在 A 上跑 10 s，在 B 上跑 15 s：

$$
\frac{\text{Execution time}_B}{\text{Execution time}_A} = \frac{15}{10} = 1.5
$$

→ **A 比 B 快 1.5 倍**。

> 注意分子分母：**慢的時間放分子**，得到的 n > 1。

---

## 4. 量測執行時間（Measuring Execution Time）

| 名詞 | 內容 | 反映 |
|---|---|---|
| **Elapsed time**（wall-clock time） | 總反應時間，包含處理、I/O、OS overhead、閒置時間 | **系統效能（system performance）** |
| **CPU time** | CPU 實際處理此工作的時間；**不含** I/O 等待與其他工作佔用的時間 | **CPU 效能** |

CPU time 再細分：

| 類型 | 說明 |
|---|---|
| User CPU time | 執行程式本身（user mode） |
| System CPU time | OS 代替程式執行的時間（system mode） |

> 不同程式受 CPU 效能與系統效能影響的程度不同（例如 I/O 密集的程式，換 CPU 幫助有限）。

> 在 Linux 上可用 `time ./a.out` 觀察：`real` = elapsed time，`user` + `sys` = CPU time。

---

## 5. CPU 時脈（CPU Clocking）

數位硬體的運作由**固定頻率的時脈（constant-rate clock）**控制。每個 clock cycle 內完成資料傳輸與運算，在 cycle 結束時更新狀態（state）——**在一個 period 之後，得到的值才是確定的**。

| 名詞 | 定義 | 例子 |
|---|---|---|
| **Clock period（時脈週期，cycle time）** | 一個 clock cycle 的長度 | 250 ps = 0.25 ns = 250 × 10⁻¹² s |
| **Clock rate（時脈頻率）** | 每秒的 cycle 數 | 4.0 GHz = 4000 MHz = 4.0 × 10⁹ Hz |

$$
\text{Clock rate} = \frac{1}{\text{Clock period}}
$$

### 時間單位換算

| 單位 | 數值 |
|---|---|
| ms（毫秒） | 10⁻³ s |
| µs（微秒） | 10⁻⁶ s |
| ns（奈秒） | 10⁻⁹ s |
| ps（皮秒） | 10⁻¹² s |

> 驗算：4 GHz → period = 1 / (4 × 10⁹) = 0.25 × 10⁻⁹ s = 250 ps ✔

---

## 6. CPU 時間（CPU Time）

$$
\text{CPU Time} = \text{CPU Clock Cycles} \times \text{Clock Cycle Time} = \frac{\text{CPU Clock Cycles}}{\text{Clock Rate}}
$$

| 項目 | 意義 |
|---|---|
| CPU Clock Cycles | Cycle **個數** |
| Clock Cycle Time | **一個** cycle 需要多少時間 |

### 改善效能的方法

1. 減少 clock cycle 數
2. 提高 clock rate

> **硬體設計者常需在 clock rate 與 cycle 數之間取捨（trade off）**：提高頻率可能讓每個工作需要更多 cycle。

### 範例：設計 Computer B

**條件**：Computer A 時脈 2 GHz，CPU time 10 s。設計 B 的目標 CPU time 為 6 s；B 可用更快時脈，但 cycle 數會變為 A 的 1.2 倍。B 的時脈需要多快？

**Step 1**：求 A 的 cycle 數

$$
\text{Clock Cycles}_A = \text{CPU Time}_A \times \text{Clock Rate}_A = 10\,\text{s} \times 2 \times 10^9\,\text{Hz} = 20 \times 10^9
$$

**Step 2**：求 B 的 clock rate

$$
\text{Clock Rate}_B = \frac{1.2 \times \text{Clock Cycles}_A}{\text{CPU Time}_B} = \frac{1.2 \times 20 \times 10^9}{6\,\text{s}} = \frac{24 \times 10^9}{6} = 4\,\text{GHz}
$$

> 時脈要加倍（2 → 4 GHz），時間卻只從 10 s 降到 6 s，因為 cycle 數增加了 20%。

## 7. 指令數與 CPI（Instruction Count and CPI）

$$
\text{Clock Cycles} = \text{Instruction Count} \times \text{CPI}
$$

$$
\text{CPU Time} = \text{IC} \times \text{CPI} \times \text{Clock Cycle Time} = \frac{\text{IC} \times \text{CPI}}{\text{Clock Rate}}
$$

| 名詞 | 意義 | 由誰決定 |
|---|---|---|
| **Instruction Count（IC）** | 程式執行的指令數 | 程式、ISA、compiler |
| **CPI（Cycles Per Instruction）** | 每道指令的**平均** cycle 數 | CPU 硬體；也受 instruction mix 影響 |

### 範例 1：同 ISA，比較兩台電腦

| 電腦 | Cycle time | CPI |
|---|---|---|
| A | 250 ps | 2.0 |
| B | 500 ps | 1.2 |

同 ISA → IC 相同，記為 I。

$$
\text{CPU Time}_A = I \times 2.0 \times 250\,\text{ps} = I \times 500\,\text{ps}
$$

$$
\text{CPU Time}_B = I \times 1.2 \times 500\,\text{ps} = I \times 600\,\text{ps}
$$

$$
\frac{\text{CPU Time}_B}{\text{CPU Time}_A} = \frac{600}{500} = 1.2
$$

→ **A 比 B 快 1.2 倍**。

> 關鍵：「Same ISA」是讓 IC 可以消去的前提。

---

## 8. CPI 細部計算（CPI in More Detail）

不同類別的指令需要不同 cycle 數時：

$$
\text{Clock Cycles} = \sum_{i=1}^{n} (\text{CPI}_i \times \text{IC}_i)
$$

**加權平均 CPI（weighted average CPI）**：

$$
\text{CPI} = \frac{\text{Clock Cycles}}{\text{IC}} = \sum_{i=1}^{n} \left( \text{CPI}_i \times \underbrace{\frac{\text{IC}_i}{\text{IC}}}_{\text{relative frequency}} \right)
$$

### 範例 2：兩種編譯結果

| Class | A | B | C |
|---|---|---|---|
| CPI for class | 1 | 2 | 3 |
| IC in sequence 1 | 2 | 1 | 2 |
| IC in sequence 2 | 4 | 1 | 1 |

| | Sequence 1 | Sequence 2 |
|---|---|---|
| IC | 2 + 1 + 2 = **5** | 4 + 1 + 1 = **6** |
| Clock cycles | 2×1 + 1×2 + 2×3 = **10** | 4×1 + 1×2 + 1×3 = **9** |
| Avg. CPI | 10 / 5 = **2.0** | 9 / 6 = **1.5** |

> Sequence 2 的指令數**較多**，卻因為 cycle 數較少而**較快**。**只看 IC 判斷快慢是錯的。**

---

## 9. 效能總結（Performance Summary）— The BIG Picture

$$
\text{CPU Time} = \frac{\text{Instructions}}{\text{Program}} \times \frac{\text{Clock cycles}}{\text{Instruction}} \times \frac{\text{Seconds}}{\text{Clock cycle}}
$$

### 各因素影響哪些項目

| 硬體或軟體要素 | 影響 | 說明 |
|---|---|---|
| 演算法（Algorithm） | IC，可能 CPI | 決定執行的指令數；若使用較多慢指令（如除法、浮點運算），CPI 上升 |
| 程式語言（Programming language） | IC、CPI | 敘述句被轉成指令；高度抽象的語言（如 Java）常需 indirect calls，使用 CPI 較高的指令 |
| 編譯器（Compiler） | IC、CPI | 編譯器的效率決定轉換出的指令與其組合 |
| 指令集架構（ISA） | IC、CPI、T_c | 影響所需指令數、每道指令 cycle 數、整體時脈速率——三項都影響 |

> 唯一能完整代表效能的是 **CPU Time（執行時間）**；IC、CPI、clock rate 單獨看都可能誤導。

---

## 解題流程：題目給什麼 → 用哪個公式

| 題目給的條件 | 使用公式 |
|---|---|
| 兩台電腦的執行時間 | n = Time_慢 / Time_快 |
| Cycle 數 + clock rate | CPU Time = Cycles / Rate |
| CPU time + clock rate，求 cycles | Cycles = Time × Rate |
| IC + CPI + cycle time（或 rate） | CPU Time = IC × CPI × T_c = IC × CPI / Rate |
| 同 ISA 比較兩台電腦 | IC 消去，比較 CPI × T_c |
| 多類指令各自 CPI 與數量 | Cycles = Σ(CPI_i × IC_i)，再除以 IC 得平均 CPI |
| 只給 frequency（百分比） | CPI = Σ(CPI_i × 比例_i) |

---

## 重點整理

| 公式 / 概念 | 內容 | 注意事項 |
|---|---|---|
| Performance | 1 / Execution time | 「快 n 倍」= Time_Y / Time_X |
| Elapsed time | 含 I/O、OS、閒置 | 反映系統效能 |
| CPU time | user + system CPU time | 不含 I/O 等待 |
| Clock rate | 1 / Clock period | 4 GHz ↔ 250 ps |
| CPU Time | Cycles × T_c = Cycles / Rate | 時脈與 cycle 數需取捨 |
| Clock Cycles | IC × CPI | |
| CPU Time（完整） | IC × CPI × T_c | 最重要公式 |
| 加權 CPI | Σ(CPI_i × IC_i / IC) | IC 多不代表慢 |
| ISA | 影響 IC、CPI、T_c | 演算法、語言、編譯器只影響 IC、CPI |
