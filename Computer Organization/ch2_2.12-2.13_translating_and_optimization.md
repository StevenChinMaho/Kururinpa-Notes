## 1. 轉譯與啟動（Translation and Startup）

```
C program
   ↓ Compiler
Assembly language program
   ↓ Assembler
Object: Machine language module ＋ Object: Library routine (machine language)
   ↓ Linker                         ← Static linking
Executable: Machine language program
   ↓ Loader
Memory
```

| 工具 | 輸入 → 輸出 | 工作 |
|---|---|---|
| **Compiler** | C → 組合語言 | 翻譯高階語言；許多編譯器**直接產生 object module**（跳過組合語言檔） |
| **Assembler** | 組合語言 → object module | 符號指令轉機器碼 |
| **Linker** | 多個 object + library → executable | 合併模組、解析跨模組的標籤與位址（**static linking**） |
| **Loader** | executable → 記憶體 | 將程式載入記憶體並開始執行 |

> 在 Linux 上可用 `gcc -S`（只到組合語言）、`gcc -c`（產生 .o object）、`gcc`（完整連結）觀察各階段。

## 2. 編譯最佳化的影響（Effect of Compiler Optimization）

以 gcc 在 Pentium 4 / Linux 上編譯（排序程式），比較不同最佳化等級（數值為圖表約略值）：

| 最佳化等級 | Relative Performance | Instruction count | Clock cycles | CPI |
|---|---|---|---|---|
| none | 1.0 | ~115,000 | ~159,000 | ~1.4 |
| O1 | ~2.4 | ~37,000 | ~67,000 | ~1.8 |
| O2 | ~2.4 | ~40,000 | ~67,000 | ~1.7 |
| O3 | ~2.4 | ~45,000 | ~66,000 | ~1.5 |

### 觀察（投影片紅圈處）

- 開最佳化後，**IC 大幅下降**，效能提升約 2.4 倍。
- 但 **CPI 反而上升**（O1 最高）——最佳化移除了大量簡單指令，剩下的指令平均更「重」。
- O1 → O3：IC **增加**、CPI **下降**，clock cycles 與效能幾乎不變。

> 驗證 1.6 節的觀念：效能由 **IC × CPI** 共同決定；只看 IC 或只看 CPI 都會誤判。

## 3. 語言與演算法的影響（Effect of Language and Algorithm）

| 版本 | Bubblesort 相對效能 | Quicksort 相對效能 |
|---|---|---|
| C/none | 1.0 | 1.0 |
| C/O1 | ~2.4 | ~1.5 |
| C/O2 | ~2.4 | ~1.5 |
| C/O3 | ~2.4 | ~1.9 |
| Java/int（直譯） | ~0.1 | ~0.05 |
| Java/JIT | ~2.1 | ~0.3 |

| 名詞 | 說明 |
|---|---|
| Java/int | JVM **直譯（interpret）** bytecode |
| Java/JIT | **Just-In-Time 編譯**：執行時把部分程式碼轉成原生機器碼 |

### Quicksort vs. Bubblesort Speedup

在各種語言／最佳化組合下，Quicksort 都比 Bubblesort 快約 **300 ~ 2500 倍**（C/none 約 2500 倍）。

> 演算法的差距（數百到數千倍）遠大於編譯器最佳化（約 2 倍）。

---

## 4. 學到的教訓（Lessons Learnt）

1. **IC 與 CPI 單獨看都不是好的效能指標**
2. **編譯器最佳化的效果與演算法有關**（Bubblesort 受益 2.4 倍，Quicksort 只有 1.5–1.9 倍）
3. **Java/JIT 明顯快於 JVM 直譯**，某些情況可媲美最佳化後的 C
4. **Nothing can fix a dumb algorithm!**（爛演算法什麼都救不了）

---

## 重點整理

| 概念 | 重點 |
|---|---|
| Compiler | 高階語言 → 組合語言（常直接產生 object） |
| Assembler | 組合語言 → object module |
| Linker | 合併 object 與 library → executable（static linking） |
| Loader | executable → 記憶體並執行 |
| 最佳化 | IC 降、CPI 可能升；看整體時間 |
| JIT | 執行時編成原生碼，遠快於直譯 |
| 演算法 | 影響最大，比最佳化重要得多 |
