## 1. 單處理器效能（Uniprocessor Performance）

以 VAX-11/780 為基準（= 1）的效能成長率：

| 期間 | 年成長率 | 原因 |
|---|---|---|
| 1978–1986 | 25%/年 | 技術進步 |
| 1986–2003 | **52%/年** | RISC 架構、ILP、時脈提升 |
| 2003–2011 | 23%/年 | 撞上 power wall |
| 2011–2015 | 12%/年 | |
| 2015–2018 | 3.5%/年 | |

> 成長趨緩的三個限制：**power、instruction-level parallelism（ILP）、memory latency**。

## 2. 多處理器（Multiprocessors）

### 2.1 Multicore microprocessors

- 一顆晶片上有**多個處理器（core）**。
- 需要**顯式平行程式設計（explicitly parallel programming）**。

### 2.2 與 ILP 比較

| | Instruction-level parallelism（ILP） | Multicore（顯式平行） |
|---|---|---|
| 誰負責平行化 | 硬體同時執行多道指令 | 程式設計師 |
| 程式設計師可見 | ❌ 隱藏（hidden from the programmer） | ✅ 必須自己寫 |
| 舊程式自動變快 | ✅ | ❌ 需改寫 |

### 2.3 平行程式設計為何困難

1. 為效能而寫程式（programming for performance）
2. 負載平衡（load balancing）
3. 最佳化通訊與同步（optimizing communication and synchronization）

## 3. SPEC CPU Benchmark

### 3.1 Benchmark 是什麼

- 用來量測效能的一組程式，應**代表實際工作負載（typical of actual workload）**。
- **SPEC（Standard Performance Evaluation Corp）**：開發 CPU、Power、I/O、Web、Cloud 等 benchmark。https://www.spec.org/

### 3.2 SPEC CPU 的計算方式

1. 量測執行一組程式的 **elapsed time**（I/O 可忽略，因此聚焦 CPU 效能）
2. 相對於參考機器正規化：

$$
\text{SPECratio} = \frac{\text{Reference time}}{\text{Execution time}}
$$

3. 以**幾何平均（geometric mean）**彙整：

$$
\sqrt[n]{\prod_{i=1}^{n} \text{Execution time ratio}_i}
$$

| 版本 | 組成 |
|---|---|
| SPEC CPU2006 | CINT2006（整數 12 支）、CFP2006（浮點 17 支） |
| SPEC CPU2017 | 最新版本 |

> 為何用幾何平均：比值的幾何平均與參考機器的選擇無關，比較結果不會因換基準而改變排名。

### 3.3 實例：SPECspeed 2017 Integer（1.8 GHz Intel Xeon E5-2650L）

| 程式 | IC (×10⁹) | CPI | Exec time (s) | Ref time (s) | SPECratio |
|---|---|---|---|---|---|
| perlbench | 2684 | 0.42 | 627 | 1774 | 2.83 |
| gcc | 2322 | 0.67 | 863 | 3976 | 4.61 |
| mcf | 1786 | 1.22 | 1215 | 4721 | 3.89 |
| x264 | 4488 | 0.32 | 813 | 1763 | 2.17 |
| xz | 8533 | 1.32 | 6290 | 6182 | 0.98 |
| … | | | | | |
| **Geometric mean** | | | | | **2.36** |

Clock cycle time 皆為 0.556 ns（= 1 / 1.8 GHz）。

### 3.4 用 1.6 節公式驗算（perlbench）

$$
\text{Exec time} = \text{IC} \times \text{CPI} \times T_c = 2684 \times 10^9 \times 0.42 \times 0.556 \times 10^{-9} \approx 627\,\text{s} \;✔
$$

$$
\text{SPECratio} = \frac{1774}{627} \approx 2.83 \;✔
$$

> 觀察：CPI 從 0.32（x264）到 1.32（xz）差距很大——**同一顆 CPU 上，CPI 隨程式而變**，這也是 MIPS 不適合當效能指標的原因（見 1.10）。CPI < 1 表示一個 cycle 可完成超過一道指令（superscalar）。

## 4. SPEC Power Benchmark

量測伺服器在**不同負載程度**下的功耗。

| 項目 | 單位 |
|---|---|
| Performance | ssj_ops/sec |
| Power | Watts（Joules/sec） |

$$
\text{Overall ssj\_ops per Watt} = \left( \sum_{i=0}^{10} \text{ssj\_ops}_i \right) \Big/ \left( \sum_{i=0}^{10} \text{power}_i \right)
$$

> 意義：**單位能量所能完成的操作數**（i = 0 到 10 對應 0%、10%、…、100% 負載）。

### 實例比較

| | Xeon E5-2650L | Xeon X5650 |
|---|---|---|
| 100% 負載功耗 | 347 W | 258 W |
| **0% 負載（閒置）功耗** | **48 W** | **80 W** |
| 閒置 / 滿載 | 48/347 ≈ 14% | 80/258 ≈ 31% |
| Σssj_ops | 26,815,444 | 4,787,166 |
| Σpower | 2,165 W | 1,922 W |
| **ssj_ops per Watt** | **12,385** | **2,490** |

> 即使完全沒有工作（0% 負載），伺服器仍消耗可觀的功率——這是 1.10 節 Fallacy 的依據。新一代（E5-2650L）閒置功耗比例明顯較低，能源效率約高 5 倍。

## 重點整理

| 概念 | 重點 |
|---|---|
| 效能成長趨緩 | 受 power、ILP、memory latency 限制 |
| Multicore | 需顯式平行程式設計 |
| ILP | 硬體自動、對程式設計師隱藏 |
| 平行化難點 | 效能導向設計、負載平衡、通訊與同步 |
| SPECratio | Reference time / Execution time（越大越好） |
| 彙整方式 | **幾何平均** |
| SPEC Power | Σssj_ops / Σpower，含 0% 負載 |
| 閒置功耗 | 不為零，可達滿載的 14%–31% |
